# ICV评分系统实现总结

## 已完成的工作

### 1. 核心模块实现 ✅

#### 1.1 规则评分器 (`src/env/rule_based_scorer.py`)

**特性**：
- 基于交通工程理论的车辆重要性评分
- 综合考虑5个维度：瓶颈区域、速度、车道位置、距离、TTC
- 基于实际路网设计的瓶颈区域参数（J5、J15、J17汇入点）
- 完整的评分分解功能（用于调试和可视化）

**代码行数**：~400行

**关键函数**：
- `compute_scores()`: 计算所有车辆的评分
- `get_score_breakdown()`: 获取详细的评分分解
- `_compute_bottleneck_score()`: 瓶颈区域评分（高斯分布平滑）
- `_compute_speed_score()`: 速度评分（分段函数）
- `_compute_ttc_score()`: TTC评分（碰撞风险评估）

#### 1.2 ICV评分GNN模型 (`src/models/icv_gnn_scorer.py`)

**特性**：
- 专门设计的图神经网络架构用于车辆评分
- 轻量级图卷积层（避免复杂GNN库依赖）
- 基于空间距离和车道信息的图构建策略
- 多层特征融合网络（64维隐藏层，3层GNN）
- Sigmoid归一化输出到[0, 1]范围

**代码行数**：~500行

**关键组件**：
- `LightweightGraphConvolution`: 轻量级图卷积层
- `ICVGraphScorer`: GNN评分模型（主类）
- `ICVGNNScorer`: 包装类，提供与规则评分器一致的接口

**模型参数**：
- 输入维度：9（车辆状态特征）
- 隐藏层维度：64
- GNN层数：3
- Dropout：0.1
- 交互半径：0.15（归一化距离）

#### 1.3 统一评分接口 (`src/env/vehicle_scoring.py`)

**特性**：
- 统一的评分接口，支持神经网络和规则两种评分方式
- 默认使用神经网络评分，失效时自动回退到规则评分
- Top-K车辆选择功能
- 模式切换功能（神经网络 ↔ 规则）
- 使用统计功能（监控评分器使用情况）

**代码行数**：~300行

**关键方法**：
- `compute_scores()`: 计算车辆评分（主要接口）
- `get_top_k_vehicles()`: 获取评分最高的K个车辆
- `switch_to_neural()`: 切换到神经网络模式
- `switch_to_rule()`: 切换到规则模式
- `get_statistics()`: 获取使用统计

## 关键设计决策

### 1. 为什么使用GNN？

**原因**：
- 车辆之间存在交互关系（跟驰、换道、汇入）
- 图结构可以自然表达这些关系
- GNN可以捕捉局部和全局的交通模式

**实现**：
- 使用空间距离构建邻接矩阵
- 车道掩码（只连接同车道或相邻车道）
- 行归一化（消息传递权重）

### 2. 为什么需要规则评分器作为备选？

**原因**：
- 提供可靠的baseline
- 神经网络失败时的回退方案
- 训练初期使用规则评分生成标签

**优势**：
- 不需要训练即可使用
- 可解释性强
- 基于交通工程理论

### 3. 为什么采用两阶段训练？

**Stage 1: 行为克隆**
- 目标：快速学习基础模式
- 方法：从规则评分器学习
- 时长：1.5-2小时
- 优势：提供良好的初始化

**Stage 2: PPO微调**
- 目标：直接优化OCR
- 方法：强化学习
- 时长：3-4小时
- 优势：端到端优化比赛指标

### 4. 适配比赛场景的参数调整

**基于实际路网分析**：
- 路网：E1 → E2 → E3 → E5 → ... → E13
- 关键瓶颈：J5、J15、J17汇入点（1500 veh/h）
- 总流量：9900 veh/h

**调整的参数**：
- 瓶颈区域：s ∈ [1200, 2200]（覆盖J15和J17）
- 车辆类型：HV（75%）、CV（25%）
- 最大速度：30 m/s
- ICV比例：10%（而非官方的25%）
